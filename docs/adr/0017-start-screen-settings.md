# 0017 — One start screen with host-drawn settings

Status: Accepted (2026-10-16; amends 0002, narrows 0015). Amended 2026-10-16: `setupInGame` games may opt out of the host difficulty (see "Amendment" below). Amended 2026-10-18: a setting declared `remember: false` is never remembered or preselected (see "Host behaviour").

## Context
Many games showed the host's difficulty select and "New game", and then a second options panel of their own (opponents, board size, variant, sometimes the difficulty again). The owner decided (2026-10-16): **one start screen for every game, drawn by the host** — "Continue" at the top when a save exists; below it "New game" with *all* settings that change the game, difficulty included; then "Start". No double difficulty selection anywhere.

## Decision
- **Declared settings.** `GameModule.settings?: SettingSpec[] | ((env: SettingsEnv) => SettingSpec[])` (packages/game-core). Kinds: `difficulty` (values `metadata.difficulties`, labels `difficulty.<id>`, optional `default` — the game's own default difficulty, else the first), `choice` (fixed values; labels `${valueKey}.${value}` message keys, or ready-made `valueLabels` only for device lists such as imported decks), `toggle`, `number` (min/max/step). Optional `hintKey` and `when: { otherId: [values…] }` (shown only while it holds; `difficulty` is referred to as `difficulty`). The function form gets the translator and the device services (decks, learning records, content languages, preferences, launch options).
- **Validation.** `validateSettings(module, locales, env?)`: unique well-formed ids (`difficulty` reserved), non-empty unique values, defaults among the values (numbers on the step grid), `when` refers to known settings and their values, at most one difficulty entry (which needs `metadata.difficulties`), every label/hint/value key present in all 16 locales. Part of the shared contract suite.
- **Passing.** `NewGameOptions.settings` (by id, without the difficulty, which stays `difficulty`) and `NewGameOptions.begin` (the player just pressed Start or "Another round": an intro-screen game may skip its "ready?" step; absent for deep links and direct starts). The host resolves every value with `resolveSettings` before passing it (unknown ids dropped, invalid values replaced by the default, hidden settings left out); games still treat the record as untrusted.
- **What the host draws** (`hostSettings`): the declared settings; with `metadata.difficulties` and no difficulty entry, the difficulty first — for every game, `setupInGame` ones included (unless a `setupInGame` game declares `settings` itself, see the amendment below). Games without `settings` therefore get exactly the old difficulty choice, now on the start screen.
- **Settings of a save** (`GameModule.settingsOf?(state)`): what a state tells about the settings it was started with (difficulty under `difficulty`). The host uses it for saves written before the envelope kept `settings`, and takes the difficulty only from it when the game implements it (the state is the source of truth, e.g. laser-circuit's version-1 saves, whose envelope names the old difficulty); otherwise the envelope's difficulty counts only when it is one of `metadata.difficulties`. When a save cannot tell every setting the start screen would show, the host shows no settings summary and, after a natural end, only "Change settings" (never "Another round" with guessed settings), and it does not write guessed settings into the save. The shared contract checks that "Another round" with what `settingsOf` tells starts the same game.
- **Host behaviour** (apps/web game page, `pages/setup-form.ts`):
  - Start screen = a `<form>` labelled "New game": one fieldset with legend per choice (≤ 4 values as wrapping radio buttons, more as a labelled select; `display` overrides), checkboxes for toggles, number inputs; hints via `aria-describedby`; hidden settings are disabled and skipped. "Continue" (focused when there is a save) above it; "Start" (submit, focused otherwise, Enter submits); a polite announcement on start.
  - Remembered per game in the host-owned preference `@settings` (validated against the current declaration on every read; device lists re-checked at Start). Start merges into it, so a setting hidden at Start (e.g. the strength while two people play) keeps its last value. Until the start screen has remembered something, a game may use what its older versions remembered in their own preferences as its declared defaults (n-back, review, chess, tic-tac-toe, Four in a Row, Stack Duel, Poker, Skat, Orbit Links, Memory, Word Guess). Amendment (2026-10-18): a non-difficulty setting declared with `remember: false` is never stored in `@settings` and never preselected from a save or the running game, so the start screen always opens on its declared default (Pixel Peel's "Any picture"); "Another round" still repeats the save's value.
  - During play the toolbar shows only **"New game"** (plus a short settings summary and the game number). It opens the start screen; the running game stays saved (paused, hidden) and "Continue" returns to it.
  - After a natural end: **"Another round"** (same settings — from the save envelope, else `settingsOf` — one deliberate press, `begin: true`) and **"Change settings"** (the start screen); only "Change settings" when the save could not tell its settings. Never an automatic next game.
  - "Continue" on a stored save restores it and focuses the game.
  - Deep links `?seed=`, `?new=1`, `?deck=` start at once with the remembered settings, `?difficulty=` overriding.
- **Save envelope** gains optional `settings` (plain record of string/number/boolean). Backward compatible; unreadable settings are dropped without discarding the game.
- **Rule:** settings that change the game are chosen **only on the start screen**. Pure display preferences (zoom, card faces, animation speed, text size, keyboard layout) and in-game navigation (level picker) may stay inside games.
- **ADR 0015 narrowed.** `setupInGame` is for setups that cannot be declared (e.g. a map editor or seat assignment). Such a game gets the same start screen as every other game — the difficulty first (from `metadata.difficulties`) plus what it declares; Start passes the difficulty and `begin`, and the game's own setup follows. Only a game with nothing for the start screen (no difficulties, no declared settings) and without a save is opened directly on its setup; "New game" leads to the start screen (Continue / Start) like everywhere else.

## Amendment (2026-10-16): setupInGame games may choose the difficulty themselves
Owner decision (Relay Command): its start screen shows only Continue/Start; the difficulty is chosen in the game's own setup next to the map.
- `hostSettings`: when `metadata.setupInGame` is true **and** the module declares `settings` (an array, `[]` included, or a function), the host shows exactly the declared settings and adds no difficulty. A `setupInGame` game that declares nothing (`settings` undefined) keeps the difficulty first. Relay Command uses the opt-out (`settings: []`, difficulty in its own setup, owner decision 2026-10-16). Games without `setupInGame` are unchanged (`[]` still gets the difficulty).
- The difficulty still flows through the host: the game reports it with `context.setDifficulty` (and `settingsOf(state).difficulty` for saves); the host validates it against `metadata.difficulties`, writes it to the save envelope, passes it to `newGame` on "Another round" and "New game", and may show it in the toolbar summary. `?difficulty=` links still pass it to `newGame`.
- With nothing for the start screen: no save → the game opens directly on its own setup (ADR 0015); with a save → "Continue" and a "New game" button (no empty settings form) that starts the game's own setup with `begin`.

## Migration plan (by groups)
Phase 1 (this ADR): core types, validation, host start screen, contract and e2e helpers (`startGame`, `submitStart`, `newGame`, `chooseSetting`), all e2e specs moved to the start screen. Then, one game per change, each removing its own duplicate options:
1. **Difficulty doubled in the game** (chess strength menu, tic-tac-toe, laser-circuit, poker, skat, card-quest): move the game's options into `settings`, delete the in-game copy, drop `setDifficulty` where it only mirrored the host.
2. **Own options panel before play** (n-back variant, node-conquest opponents/map, visual-search, review deck, word-guess language, memory deck…): declare them; keep only display preferences in the game.
3. **Setups that cannot be declared** (relay-command map/seats): keep `setupInGame`; Relay Command chooses its difficulty in its own setup via the opt-out above. Card Quest moved its whole setup into `settings` (PR #51) and no longer uses `setupInGame`.
4. **Intro screens** adopt `begin` to skip a redundant "ready?" step after Start; what the intro explained (rules of the round, keys) stays visible as a compact line during play (signal-watch, visual-search, distractor-control, n-back).

## Consequences
+ One predictable flow for every game; no double difficulty; settings are visible, labelled, keyboard- and screen-reader-friendly by construction.
+ Settings are data: validated in all 16 locales and sampled in the contract (deterministic, valid state for any combination; no throw on junk).
− Games must migrate their own option panels; until then some games still show options both on the start screen (difficulty) and in the game.
− "New game" is one more step during play (start screen, then Start); "Another round" keeps the one-press repeat.

## Amendment (2026-10-30): groups in a long choice
A choice may declare `groups: { labelKey, values }[]`. The host's select shows the values in no group first, then one `<optgroup>` per group (label from the game's namespace, values in the group's order); radio buttons ignore groups. `validateSettings` checks that each group lists known values, that no value is in two groups, and that every `labelKey` exists in the game's locales. First use: Pixel Peel's picture select (about 95 pictures in five groups, each group starting with "Any <kind>").
